# A 股仪表盘盘后更新任务书

> 派工：更新 A 股 YYYYMMDD 盘后数据，核对资金口径与参与者数据，生成快照和研判，并按本次授权交付。接手时先确认生产脚本的位置。

公开子站在本仓 a-share/。[完整手册](ashare-data-pipeline-handoff.md)列出来源、九步流程、字段契约和原执行环境。正常调度为上海交易日 19:00。日期使用 Asia/Shanghai。

## 首次换人先核对材料

| 材料 | 在哪找 | 缺失时还能做什么 |
|---|---|---|
| 网页和历史发布样本 | [前端与数据目录](../a-share)、[日期索引](../a-share/data/dashboard-meta.json) | 可直接复核页面、结构与已发布数值 |
| 采集、计算、组装、构建及验收脚本 | 原手册的生产工作区 reports/；完整 RUNBOOK.md、collect_data.py、collect_participants.py、calc_日期.py、assemble_日期.py、build_dashboard.py、verify.js、station_update.py 等。当前公开子站目录未提供完整执行包 | 向原执行者取得获准访问的私有版本、依赖和最近一次成功样本；记录具体缺件及已验证的步骤。凭网页快照只能核验既有产物 |
| 中途接手所需输入 | 目标日 data/daily/ 归档、参与者滚动序列、补源证据、计算结果及采用的脚本版本 | 对已有产物续验；保留私有可访问位置，回执写清最后验证成功的阶段 |

## 有生产工作区时执行

1. 按交易日历、行情观察日和上次快照确定目标日。源端尚未更新时，保留“待披露”状态。历史快照存在则先核验完整性，再决定是否补录。
2. 在生产工作区分别执行 `python collect_data.py YYYYMMDD`、`python collect_participants.py YYYYMMDD`。先核对本地版本参数；耗时采集按原手册后台运行并持久化日志。超时单独重试失败来源，保存成功分项。
3. 按手册 §3–5 补资金流、北向成交和收评。主力净额与超大单/大单拆分逐字段标来源及单位，使用代理风格时标出并留待复核。沪市当日融资与两市滞后两融分别标市场范围和观察日，北向成交额与净买额分列。确实拿不到的字段保留原因。
4. 复核并运行目标日的 calc 和 assemble 脚本，随后运行 build_dashboard.py、verify.js；参数按交接版本的 RUNBOOK。对照最近合格快照检查必填字段，涨停行业等动态键允许变化。核对八张图、页面 JS 错误、空白或溢出、三大指数高低收、资金流单位、参与者摘要及研判卡；按原手册处理缺失项。
5. 在生产工作区用 `python station_update.py YYYYMMDD` 对候选部署检出入库，检查只产生预期的 a-share/data 变更。保存经验证的快照和索引。发布阶段依据已有授权及原手册执行，核对推送目标和将要提交的文件，并保留期货、美股及其他站点数据。
6. 发布后读[线上索引](https://evanyfm.github.io/futures-workstation/a-share/data/dashboard-meta.json)的 `dates[0]`（历史补录则检查目标日在列表且最新日不倒退），检查目标 snapshots/YYYYMMDD.json 可读、JSON 内日期一致，在[子站](https://evanyfm.github.io/futures-workstation/a-share/)选中目标日复核研判与一项当日资金数据。任务含独立日报时，同时交付经核验的 HTML 与核心结论。

## 交接回执

每阶段完结就把以下一行更新到本次任务的私有交接记录，附下一位执行者有权读取的产物链接。成功发布后可以直接引用公开版本。凭据、登录态和未经许可的原始数据留在获准环境。

```text
目标日期/截止时点＝　源码提交＝　阶段＝　输入与候选产物位置/版本＝
采集或回退缺项及观察期＝　验证（通过/失败/跳过）＝
发布（未要求/待授权/已推送/线上已核验）及提交＝　下一步命令或具体阻塞＝
```

同日接力先核对目标日期、代码版本及产物，再从首个未完成阶段继续。同一部署仓有并行提交时，在干净基线上准备变更，只暂存本站允许路径；远端前移后核对差异、重验并正常推送。已发布历史的修订单列原版本、差异及原因。发现新问题，在私有交接记录写下“来源和指标、影响日期、症状或样本、临时处置、恢复判据、修复或测试链接”；重复发生时引用原记录，公开仓只放适合公开的内容。
